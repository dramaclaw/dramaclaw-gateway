# DC Media Adapter Development Guide

This guide explains how to add a provider adapter for `DC-Media-Protocol v1`
to RelayClaw CE. The protocol definition in `dc-media-protocol.md` at the
repository root is authoritative.

## Before You Start

1. Check whether an existing New API adapter already supports the target API.
2. Add or extend a dedicated adapter only when common fields cannot be converted correctly.
3. Do not infer a DramaClaw business mode from a model name. The request shape must be derived from its media inputs.
4. Do not migrate commercial RelayClaw billing expressions, call auditing, result archiving, or operational features.

Video requests are normalized, validated for mutually exclusive inputs, and
classified by `relay/common.ValidateDCMediaTaskRequest`. Adapters must preserve
media roles: the top-level `image` is the first frame, while
`metadata.reference_images` always contains reference images. Never promote the
first reference image to the first frame.

## Directory and Registration

Place asynchronous media adapters under `relay/channel/task/<provider>/`. A
complete adapter usually needs to:

- implement `relay/channel.TaskAdaptor`;
- register its channel type in `relay/relay_adaptor.go`;
- declare its channel number, name, and default URL in `constant/channel.go`;
- include protocol conversion tests;
- optionally implement `channel.TaskCanceller` when the provider supports safe per-task cancellation.

`TaskAdaptor` separates validation, request construction, submission response
parsing, task querying, and query response parsing. Public task IDs and provider
task IDs must be stored separately. Clients may only see the `task_*` ID
generated by RelayClaw CE.

## Request Conversion

Obtain the normalized request from `relaycommon.GetTaskRequest(c)`, then process
it in this order:

1. Call `ValidateDCMediaTaskRequest` to determine the request shape.
2. Validate provider-specific limits for media counts, duration, aspect ratio, and resolution.
3. Map every media type to the fields or roles required by the provider.
4. Preserve explicit `false`, `0`, and all non-blank valid values; use pointer types for optional scalar fields.
5. Reject unsupported combinations before sending an upstream request. Never drop media and continue submitting.

Return stable local errors with `TaskErrorWrapperLocal`. Common error codes
include:

- `unsupported_media_combination`
- `invalid_media_request`
- `invalid_dimensions`
- `invalid_auto_duration`
- `task_cancellation_unsupported`

Provider errors may retain a sanitized request ID and a readable message, but
must not return API keys, authorization headers, or complete sensitive request
bodies.

## Asynchronous Tasks

After task creation succeeds, `DoResponse` returns the provider task ID, which
the task model stores in `PrivateData.UpstreamTaskID`. `FetchTask` must query
using only that upstream ID. `ParseTaskResult` maps provider states to
`QUEUED`, `IN_PROGRESS`, `SUCCESS`, or `FAILURE`.

Store result URLs in private task data. Results that require authentication or
are hosted on a private network should be served through
`/v1/videos/{task_id}/content`; never place channel credentials in a URL.

Cancellation succeeds only after the provider confirms that the specified task
has been cancelled. A global interrupt endpoint cannot implement per-task
cancellation. Return `task_cancellation_unsupported` when cancellation is not
supported instead of changing only the local state.

## Testing Requirements

Each adapter must cover at least:

- text-to-video and single-image requests;
- separation of first-frame and reference-image roles;
- supported combinations of multiple images, videos, and audio files;
- rejection of unsupported combinations before an upstream request;
- prevention of provider task ID exposure through public task IDs;
- state, result URL, and error mapping;
- queued, running, completed, and repeated-cancellation cases when cancellation is supported.

Common verification commands:

```bash
go test ./relay/common ./relay/channel/task/<provider>
cd relaykit && GOWORK=off go build ./...
cd web && bun run typecheck && bun run build
```
